## Target architecture

```
 clients (Factory runtime / Station / DSM adapters)
        │  proposals (never direct DB connections)
        ▼
 ┌─────────────────────┐      ┌──────────────────────────┐
 │  MS-08 Writer        │─────▶│ shared authoritative      │
 │  (single lease       │ CAS  │ control store (SQLite     │
 │   holder, fenced)    │      │ ledger, MS-00 schema)     │
 └─────────────────────┘      └──────────────────────────┘
        │ ack {seq, hash, disposition, fencing_token}
        ▼
 per-lane observation shards   +   local emergency journals
```

- **Shared authoritative control store**: one ledger file; storage-level CAS is
  the backstop even if the Writer role is violated.
- **Dedicated MS-08 writer**: the only process holding the write lease; only it
  executes `BEGIN IMMEDIATE` transactions.
- **Per-lane observation shards**: materialized from the committed journal in
  seq order; never mutate control state. Stale shard reads are labeled with the
  shard's cursor `(seq, hash)`.
- **Local emergency journals**: when the writer is unreachable, a lane appends
  locally with the same envelope (`event_id`, payload, hash link); drained into
  the writer on reconnect as ordinary proposals; never authoritative.

**Scope: single host.** Multi-host writer failover requires a consensus-backed
lease quorum and is **unsupported pending a consensus decision**.

## IPC / API contract (normative for any binding)

| Request | Fields | Semantics |
|---|---|---|
| `propose` | `event_id` (idempotency key), `domain`, `kind`, `payload`, `expected` (CAS precondition or `null`), `writer_token` (advisory) | Submit one mutation. Server assigns seq. |
| `read` | `domain`, `key`, `min_seq` (optional) | Bounded snapshot read; if `min_seq` beyond head, return `BEHIND`. |
| `acquire_lease` | `writer_id`, `ttl_ms` | Claim CAS; returns new durable `fencing_token`. |
| `renew_lease` | `writer_id`, `fencing_token`, `ttl_ms` | Bumps token (renewal invalidates pre-renew in-flight writes). |
| `drain` | `events[]` | Batch of `propose`; each resolved independently. |

Every `propose` ack:
```json
{"seq": 42, "hash": "sha256:…", "disposition": "accepted|duplicate|rejected",
 "fencing_token": 7, "reason": null}
```
- `disposition=duplicate` returns the *originally stored* `{seq, hash}`.
- `disposition=rejected` carries a typed `reason`: `schema`, `ownership`,
  `stale_fencing`, `cas_conflict`, `illegal_transition`, `lease_lost`,
  `writer_unavailable`. UNKNOWN/BLOCKED-class reasons are never coerced to
  `accepted`.

## Ordering normative rule: commit-before-ack

For every `propose` with idempotency key `event_id`:

1. **Validate** — schema, ownership, fencing, transition legality. Fail ⇒
   reject, nothing written.
2. **Dedupe** — `event_id` already journaled ⇒ return stored `{seq, hash}`
   with `disposition: "duplicate"`.
3. **Write** — state CAS + event append in one `BEGIN IMMEDIATE` transaction,
   `synchronous=FULL`.
4. **Commit-before-ack** — ack returned only after `COMMIT` returns. Crash
   between write and ack ⇒ client retries same `event_id` ⇒ resolves at step 2
   as `duplicate`. **No ack before commit, no commit without event append, no
   event append outside the state-mutation transaction.**
5. Ambiguous `COMMIT` result ⇒ discard the connection, enter startup
   reconciliation before serving further writes.

## CAS / outbox protocol

- **State CAS**: mutation commits only if `expected` matches the current row.
  Conflict ⇒ `rejected/cas_conflict`, nothing appended.
- **Outbox**: every accepted event is the outbox record. Consumers replay the
  journal by cursor; delivery is at-least-once; consumers dedupe by
  `event_id`. Lost delivery is recovered only via outbox retransmission.
- **External adapters**: an adapter incapable of fencing requires an
  idempotency proxy (durable key `(resource, fencing_token, effect_id)`,
  journaled admission, typed outcomes `PROXY_ADMIT` / `PROXY_DEDUP` /
  `PROXY_REJECT_STALE`) or the integration **loses the effectively-once
  classification** and receipts must say `at_least_once_external`.

## Writer lease and fencing tokens

1. Exactly one writer acquires the lease via claim CAS against the well-known
   control row (`plan_hash='__control__'`); success increments a **durable**
   `fencing_token` stored in the ledger (never reset across restart; reloaded
   at reconciliation Step 1).
2. Renewal also bumps the token; tokens are strictly monotonic per ledger
   forever.
3. Every proposal carries `(writer_id, fencing_token)`; the writer rejects any
   token below the highest it has durably issued (`stale_fencing`), and the
   storage CAS predicate independently rejects stale generations (defense in
   depth).

## Takeover / failover (single host)

1. New candidate acquires only via the claim CAS; concurrent same-ledger split
   commit is impossible (`BEGIN IMMEDIATE` write lock + bumped generation).
2. Takeover ⇒ run startup reconciliation (MS-00 §Reconciliation Steps 0–6)
   **before** accepting proposals.
3. The fenced-off old writer's next proposal fails fencing.
4. Unreadable lease table ⇒ fenced-off recovery epoch (`FENCING_UNAVAILABLE`)
   rather than guessing tokens — UNKNOWN is not PASS.
5. Multi-host failover: unsupported. A second host MUST NOT attempt claim.

## Failure model (normative)

| Failure | Required behavior |
|---|---|
| Writer crash after COMMIT, before ack | Client retries same `event_id` → `duplicate`. |
| Writer crash mid-transaction | Rollback; no partial state, no orphan event. |
| Duplicate client (retry, replay, drained journal) | Dedupe by `event_id`; stored `{seq, hash}` returned. |
| Stale writer (lease lost, still alive) | Fencing rejection + storage CAS backstop rejection. |
| Scheduler/writer unavailable | Lanes append to local emergency journals; `writer_unavailable`; drain on reconnect dedupes. |
| Ambiguous COMMIT | Discard connection, reconcile before further writes. |
| Unparseable state on read-back | Fail closed `unknown`; never retyped. |
| Lease-table loss | `FENCING_UNAVAILABLE` recovery epoch; re-register at max(observed token)+1. |
| Two hosts attempt write | Unsupported; no correctness claim. |
