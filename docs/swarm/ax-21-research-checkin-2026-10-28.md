## 2. Loopback transport: conditional exposure path and threat-model correction

**Direct source observation — #546 predecessor:** `MeshWorkerClient` already accepts HTTPS remotely but rejects non-loopback HTTP; `urllib.request.build_opener(ProxyHandler({}), NoRedirect())` bypasses environment proxies and prohibits redirects for the same fetch/request opener. Thus the broad hypothesis that the existing client permits *arbitrary remote plaintext HTTP*, or automatically follows credential-bearing redirects, is contradicted by the source. Do not report a demonstrated credential disclosure.

**Residual boundary:** The predecessor permits literal `http://localhost` and lets the OS resolve that hostname. A compromised/unexpected resolver mapping could direct a bearer token and content to a non-loopback address. This is a **conditional source-derived exposure path**, not observed exploitation, a verified malicious hosts entry, or an actual network trace.

**#551 correction observed in diff:** URL input validates type, control/whitespace characters, missing host, invalid/zero port, backslash, userinfo including empty userinfo, and query/fragment delimiters; error text does not echo untrusted URL input. HTTP `localhost` is canonicalized to numeric `127.0.0.1`; explicit `127.0.0.1` and `[::1]` remain accepted, as do HTTPS path prefixes. Redirect/proxy controls are preserved. A local malicious/wrong listener can still receive the token, and an SSH forwarding destination may have a plaintext final leg. No SSH host-identity, tunnel-ownership, native TLS, IPv6-only runtime, or multi-host test occurred. End-to-end HTTPS may be appropriate where the local host/listener is not trusted; HTTPS alone must not be described as evidence of trust in the remote application.

## 3. Integrity failures: existing durable observation, new structured classification

**Direct predecessor observation:** In #546 `MeshState.admit_message`, `MeshEnvelope.parse` failures already pass through `except ContractError`, which calls `dead_letter(... operation="message.validation" ...)` before rethrowing. The server then returns HTTP 400. Thus a hypothesis that a mismatched digest was entirely **unobserved** is false for the inspected parent. Durable dead-letter persistence is not the same as an alert being delivered to an operator.

**New candidate #551:** A well-formed but incorrect payload digest now raises `MeshIntegrityError` (subclass of `ContractError`) with stable `MESH_PAYLOAD_DIGEST_MISMATCH`. Admission records `message.integrity` and a structured WARNING with event code, operation and rejected outcome. The added telemetry path avoids attacker-selected payloads, identifiers, tokens, artifact references and digests; malformed digest syntax remains ordinary contract validation. The parser itself stays free of logging. HTTP 400 and admission authority checks are preserved. This is **instrumentation/classification progress**, not proof that an external collector, on-call alert route, retention service, or incident-response process receives the event.

**Negative controls in added tests:** Inline and artifact-reference mismatches, syntactically invalid digests, absence of message admission, one warning per mismatch, durable classification, redaction, and a real authenticated local Station HTTP 400 response are asserted by the candidate's tests. No real credential or production traffic was used.

## 5. NATS/Synadia interoperability: research-only correction, no adapter

Read the immutable [Synadia core protocol draft](https://github.com/synadia-ai/synadia-agent-sdk-docs/blob/c48cea5f07965cc8fd4054e120459f1833b3ed2b/core-protocol.md) directly; it is v0.3.0 draft and **does contain §13 optional signed sender identity**. That supersedes a categorical reading of the May article as specifying no strong sender identity. The protocol still describes core NATS streaming as at-most-once, and excludes E2E encryption and JetStream-backed at-least-once streaming. The [Python host identity implementation](https://github.com/synadia-ai/synadia-agents/blob/ed9aefbf0f3ae254451fa6ff4330b8dc47f00a33/agent-sdk/python/src/synadia_ai/agent_service/identity.py) uses an **in-memory per-instance nonce cache** with capacity and eviction caveats. A verified signature does not independently grant Station enrollment, project authority, durable receipt acceptance or provider-side exactly-once effects.

Issue #550 correctly scopes a **deferred post-v1 sidecar experiment** and retains multi-tenant/account isolation, signed-identity downgrade, nonce/replay, chunk-loss, cancellation, fenced authority and budget unknown-state tests as future controls. This is protocol/source evaluation, **not** a new executed experiment or proof of interoperability. No extra v1 blocker, cross-swarm coordinator, or autonomous remote orchestration is established.
