# R0–R5 preparation commitment

The accompanying protocol is **blocked, not confirmatory-frozen**. It commits the
current preparation choices and public fixture population without representing
synthetic alerts as executable, independently graded software tasks. No model
calls or numerical results were collected to prepare these files.

The current measured Factory runner implements `single`, `fixed`, and `dynamic`.
Those are not an evidenced mapping for the six R0–R5 interventions. The original
`study freeze` runner's eight obligation policies are also a different experiment.
Neither mapping is silently substituted here.

## Offline check

From the repository root:

```bash
python -m residual.eval.protocol \
  --protocol docs/evaluation/r0-r5.protocol.json \
  --protocol-sha256 "$(cut -d ' ' -f1 docs/evaluation/r0-r5.protocol.sha256)"
```

Success means the preparation artifact and bundled workload match their byte
commitments. Add `--require-frozen` to verify that confirmatory readiness is
rejected. The companion digest detects accidental changes; it is not an independent
preregistration or signature. Retain its digest externally before collecting data.

## Decisions already recorded

The JSON records ten repetitions, paired schedule seeds, fixed-model policy,
proposed temperature zero, cache separation, no post-result exclusions, complete
scheduled denominators, explicit unknown grades/usage, primary metric definitions,
and trial output fields. Seeds control scheduling only. The bundled sixteen prompts
and ordered population are bound by both byte and workload manifest hashes.
These are preparation choices, not claims of statistical power or live adapter support.

Raw correctness uses independently graded raw proposals; accepted correctness uses
the independently graded accepted tree. Preserve both identities. Unknown raw grades
make `P_X` a conservative observed-correct fraction, not an unbiased correctness
estimate. Unknown accepted grades yield an AER interval; they cannot be silently
counted as correct. Zero accepted outputs leave conditional metrics undefined.

## Required before a separate confirmatory freeze

1. Define each R0–R5 intervention and bind its approved execution adapter and plan.
2. Supply independent task families, graders and explicit task-to-plan mapping;
   record authoring provenance and contamination limits.
3. Select one immutable provider/model identity and qualify actual sampling,
   retry, usage, pricing and prompt-rendering behavior on separate smoke inputs.
4. Bind system prompts, verifier implementation/policy revisions and exact budgets.
5. Retain the merged M4 commit/tree, namespace qualification and independent review.
6. Generate and retain the exact paired schedule and specify the power/effect-size
   and inference plan, or keep results explicitly descriptive.
7. Issue a new immutable protocol commitment before any confirmatory observation.

A boolean change cannot enable live execution: the v1 checker explicitly rejects
ready/frozen claims. Future adapter qualification needs an implementation change and
review. Model degradation and heterogeneous routing need separate preregistered
extensions; they do not change the fixed-model study after its results are observed.
