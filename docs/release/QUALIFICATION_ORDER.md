# Demo Qualification Order

Use this order so later evidence cannot mask an earlier boundary failure:

1. source/unit/publication contracts;
2. deterministic provider fixture contracts;
3. generated artifact identity;
4. generated desktop WebVM proof;
5. generated narrow Chromium proof;
6. merge exact qualified head;
7. first production Pages deployment;
8. published exact-SHA desktop WebVM proof;
9. published exact-SHA narrow Chromium proof;
10. published real Puter SDK load proof;
11. real authentication/inference acceptance when claimed;
12. physical target-device acceptance when claimed.

Stop on the first required failure and retain it. Do not skip forward and use a later green layer to overrule it.
