## 1. Hard execution gate (binding dependency)

R0–R5 live execution **may not start** until ALL of the following hold, each with retained machine-readable evidence:

1. **M4 capable-runner qualification passes** on the exact merged-main commit/tree intended for the study (tracked as issue #88 / the preflight lane). The qualification record MUST match schema `residual.m4-qualification.v1` (per PR #90 `docs/evaluation/launch-preparation.md`), with `main_sha`, `main_tree`, `pr81_merged: true`, `issue63_closed: true`, `independent_audit: "PASS"`, and per-check entries with `conclusion: "success"` and matching `head_sha`.
2. **The Linux namespace probe (`residual.factory.m4_sandbox.probe_isolation`) returns PASS** on the actual execution host. **Namespace-skip results are non-qualification**: any test skipped because namespace creation was denied records UNKNOWN and is a blocker, never a pass (per PR #91 trust lane: 13 sandbox probes skipped/UNKNOWN = INCOMPLETE).
3. The frozen R0–R5 adapter implementations for R1–R5 exist, are reviewed, and their file SHA-256 digests are recorded in the run ledger. Until then `live_execution_enabled` remains `false` and `--mode live` returns exit code 2 before any preparation or provider access (PR #90 launcher semantics, retained).
4. The confirmatory corpus exists with content hashes filling the `BLOCKED-UNTIL-GENERATED` slots of `R0_R5_CORPUS_MANIFEST.json`, generated by the pinned procedure in §5.
5. The immutable model/provider identity is resolved by the frozen selection rule (§4) and recorded; smoke qualification used inputs disjoint from all confirmatory families.

Fixture/development results (the fw1-* workload, the VC-* adversarial corpus, synthetic-demo bundle, engineering envelope numbers) MUST NEVER be promoted into research claims. Reports built from them carry `evidence_level: "development_fixture"` and `publication_ready: false`.

## 3. Fixed models, sampling, seeds, schedule

- **Same model across all configurations** (`same_model_across_configurations: true`). Primary-study model is tier **S**, resolved by the frozen outcome-independent rule in §4 before any confirmatory outcome is observed.
- **Sampling:** `temperature: 0.0`, `top_p: 1.0`, `max_output_tokens: 512` (matching main's `CONTROLLED_CONSTANTS`; live runs must re-pin these fields with the real provider and set `evidence_level: "live_model"`). Provider-side seed support is recorded, never assumed; **seeds control schedule ordering only**.
- **Repetitions:** 10 per task per configuration. Schedule seeds (one per repetition, schedule-only): `20260914, 20260915, 20260916, 20260917, 20260918, 20260919, 20260920, 20260921, 20260922, 20260923` (from PR #90 protocol JSON; retained by both drafts).
- **Design:** balanced — 3 tasks per family, ≥30 independent task families; the exact family count F is the smallest multiple of 10 in [30..200] meeting the frozen power rule (see `R0_R5_ANALYSIS_PLAN.md` §Power). F is recorded in the corpus manifest when generated; it is never increased after outcome access.
- **Ordering:** paired task/repetition blocks; within each block, deterministic shuffle of configuration IDs with `random.Random(seed)`; the exact precomputed schedule is retained before execution. Configurations are interleaved within blocks against identical immutable starting artifacts. Cross-trial caches disabled; learned controllers reset to the same pre-frozen state.
- **Exclusions:** none. `exclusions: []`. No post-result exclusions, no replacement runs; recovery preserves original identities and never counts as a new repetition.

## 4. Model selection rule (frozen, outcome-independent)

From PR #91 `docs/program/science/models-routing.md`, binding for this protocol:

1. Retain a dated candidate catalog: provider, immutable model ID, family ID, documented capacity ordering, context/output limits, supported parameters, region, release date, list prices, primary-source URL and content hash. Exclude deprecated models, preview aliases, hidden-routing gateways, unresolvable revisions.
2. Choose the lexicographically first `(provider_id, model_family_id)` with ≥3 eligible, strictly ordered capacity tiers. Within that family sort by `(capacity_rank, immutable_id)`: smallest = **W**, largest = **S**, index `floor((n-1)/2)` = **M**.
3. **L** = eligible local model with largest published parameter count whose frozen quantized weights + KV cache + 20% memory reserve fit the predeclared machine, batch size 1; ties broken by `(publisher, immutable_id, weights_sha256)`.
4. No reranking after measuring correctness; a provider identity drift ends the cohort (new cohort = new pre-results lock, reported separately).

Primary R0–R5 uses **S** for every model-generating role. Degradation (R0/R4/R5 × S/M/W/L) and heterogeneous routing (H0–H3) are prespecified descriptive extensions, not part of the confirmatory family.

## 6. Verifier and acceptance policy (frozen)

- Accept only on verifier state `PASS`. Non-accepting states `FAIL`, `UNKNOWN`, `ERROR`, `SKIPPED` all refuse acceptance and are reported separately (PR #90 protocol `verifier` block; PR #91 INV-01).
- Verifier implementation SHA-256 and policy revision are recorded per run (currently `null` → `BLOCKED-UNTIL-QUALIFIED`).
- Raw proposals and accepted trees are graded separately by a separately versioned independent grader; grader identity/revision recorded. Verifier PASS never implies independently correct; rejected candidates are not labeled incorrect by rejection.
- M5 completion semantics (PR #90 repairs, retained): unsupported verifier states are rejected (not coerced), duplicate verification-result IDs are rejected, and a late abort/deadline takes precedence over completion.

## 9. Artifact naming and retention

- Run ID: `r0r5-<UTCYYYYMMDD>-<short-commit>-<seq>`; immutable once created.
- Bundle layout: `residual.experiment-bundle.v1` (PR #91 `docs/program/reproduction/bundle-v1.md`) — manifest.json with per-artifact SHA-256 and byte lengths; metadata/{environment,git,workload,models,prompts,protocol}.json; records/{cells,usage,timing,failures}.jsonl; evidence/{receipts,scheduler,verifier}.jsonl; streams/{stdout,stderr}.bin; reproduce.txt; attachments/.
- One terminal record per scheduled cell; statuses `completed|timeout|error|not_run|missing`; grades `correct|incorrect|unknown`; `null` is never zero; raw and accepted artifacts graded separately; receipts bind accepted tree and verifier revision.
- Retention: raw records, receipts, accepted-tree identities, schedule, and environment capture are retained indefinitely; bundles are immutable — corrections produce a new bundle ID and preserve the original.
- The manifest SHA-256 and protocol SHA-256 are retained through an independent external channel before outcome access (this repository does not supply that registry).
