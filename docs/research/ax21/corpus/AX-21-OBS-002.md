`agents.defaults.model.primary` has causal authority over fresh-session model
selection on the Wrench/DELL7320 seat.

The only intended selection mutation was:

`kimi/kimi-for-coding -> moonshot/kimi-k2.6 -> kimi/kimi-for-coding`.

The systemd gateway independently logged successful hot reload of
`agents.defaults.model.primary` after both mutation and restoration. No

## Evidence boundary: gateway transport was not proven

The probe command `openclaw agent` attempted to use the local gateway but hit
a scope-upgrade/pairing requirement. It then reported embedded fallback:

- requested path: local gateway;
- actual probe execution path: embedded fallback;
- fallback source: gateway transport failure.

A/B/C all used the same fallback path, so the causal comparison for
configuration-driven fresh-session selection remains internally consistent.

However, this receipt does **not** establish that the systemd gateway itself
mediated the A/B/C model executions. The correct claim split is:

- configuration selection authority: **PASS**;
- systemd hot-reload observation: **PASS**;
- A/B/C reversibility: **PASS**;
- semantic restoration: **PASS**;
- production-session stickiness: **PASS**;
- gateway-transport causal binding: **NOT_PROVEN / blocked by F-2**.

Do not relabel this record as proof of gateway-mediated fresh-session binding.

## F-1 — hosted provider capacity degradation

**Classification:** CONFIG / FLEET-RELEVANT / ENVIRONMENTAL

The selected Moonshot path returned a real billing-class 429 indicating that
the configured account was suspended for insufficient balance. The raw
credential is not retained in this normalized corpus record.

The same seat also had Kimi monthly-quota exhaustion. Therefore the configured
hosted-provider surface was degraded even though a local Ollama capability was
available but not wired into this selection path.

This is not a P3.3 selection-authority failure. It is a fleet-capacity finding
that should be checked independently on seats relying on the same provider
class.

## F-2 — CLI-to-gateway scope negotiation / silent execution-path change

**Classification:** SOURCE/CLI / TRANSPORT-PROVENANCE / D-5 FAMILY

The local CLI-to-gateway path requested additional scopes and required pairing.
The non-interactive probe then executed through embedded fallback.

Research significance: an automation can believe it is testing gateway-mediated
behavior while actually testing embedded behavior unless the receipt records
the requested and actual execution transports.

This motivates an explicit transport-provenance contract for future AX-21 and
RESIDUAL receipts.

At minimum, transport-sensitive receipts SHOULD retain:

- requested transport;
- actual transport;
- fallback source/reason;
- gateway process identity;
- session identity;
- provider;
- model;
- configuration generation/revision.

A successful model/tool result MUST NOT by itself establish that the requested
transport or authority surface actually mediated execution.
