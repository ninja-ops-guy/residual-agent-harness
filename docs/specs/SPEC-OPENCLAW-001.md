# SPEC-OPENCLAW-001 — OpenClaw Execution Engine Integration

Status: Implemented candidate
Target: Residual v0.5.x

## Purpose

Integrate OpenClaw as a heterogeneous execution substrate beneath Residual without delegating Residual's policy, verification, evidence, scheduling, or receipt authority.

**Authority rule:** OpenClaw executes; Residual decides whether the execution counts.

## Requirements

### OC-001 — First-class engine
`OpenClawEngine` MUST implement the existing `ExecutionEngine` protocol and MUST be registerable in `CapabilityRouter` without router-specific branching.

### OC-002 — No framework dependency
The integration MUST use the Python standard library by default. OpenClaw is reached through its Gateway HTTP surface; importing Residual MUST NOT require an OpenClaw Python package.

### OC-003 — Explicit configuration
Configuration MUST be immutable and MUST bind at least: gateway URL, model, timeout, capabilities, locality, authentication source, and declared OpenClaw version.

### OC-004 — Gateway boundary
Execution MUST target the OpenClaw Gateway OpenAI-compatible `/v1/responses` endpoint. The adapter MUST NOT invoke shell commands or mutate OpenClaw configuration.

### OC-005 — Authentication hygiene
Bearer credentials MUST be read from explicit configuration or an environment variable and MUST NOT be copied into `EngineResult`, traces, observations, receipts, exceptions, or request metadata returned to callers.

### OC-006 — Residual contract remains authoritative
OpenClaw tool policy, sandboxing, runtime selection, and provider safety controls are downstream controls. They MUST NOT replace Residual WorkerContract enforcement, verification, brakes, evidence validation, or HITL.

### OC-007 — Fail-closed observed tool boundary
When a task supplies `allowed_tools` (directly or in `worker_contract` metadata), every tool call observed in the OpenClaw response MUST be checked by Residual. An observed tool not in the allowlist MUST terminate normalization/execution with `ContractError`.

### OC-008 — No fabricated enforcement
If the Gateway response does not expose a fact (for example OS sandbox state or exact runtime identity), the adapter MUST NOT claim it was verified. Missing runtime identity MUST be recorded as unverified, not inferred from requested model/configuration.

### OC-009 — Provenance
Every successful `EngineResult.raw_metadata` MUST include the adapter identity, gateway origin without credentials, model, observed OpenClaw runtime identity when available, and `residual_policy_authoritative=True`.

### OC-010 — Usage normalization
The adapter MUST normalize total token usage when supplied either as `total_tokens` or as input/output token counters. Absence of usage MUST remain `None`.

### OC-011 — Candidate normalization
The adapter MUST normalize common OpenAI-compatible response shapes, including `output_text`, Responses API message content, and chat `choices`, while preserving unknown payloads rather than silently discarding them.

### OC-012 — Tool-call normalization
Tool calls MUST be normalized into immutable mappings containing at least the tool name when it can be determined. Raw secret-bearing request headers MUST never be exposed.

### OC-013 — Deterministic request envelope
For identical `TaskSpec`, `ContextAssembly`, and immutable adapter configuration, the JSON request body generated by the adapter MUST be deterministic.

### OC-014 — Context isolation
Context MUST be serialized into a distinct, labelled input section. The adapter MUST NOT mutate `TaskSpec`, `ContextAssembly`, or caller-owned mappings.

### OC-015 — Cancellation/timeout behavior
Gateway calls MUST use the configured wall-clock timeout. Transport timeout/failure MUST propagate as an execution failure; the adapter MUST NOT return a successful candidate from a partial response.

### OC-016 — Health semantics
`health()` MUST report static adapter readiness without performing hidden network I/O. A malformed gateway URL or missing model is `UNAVAILABLE`; a configured adapter is at least `DEGRADED`, and may be `HEALTHY` when explicit auth material or a test/injected transport is present.

### OC-017 — Injection seam
The engine MUST support an injected transport callable for deterministic unit tests and custom deployments. The callable receives endpoint URL, JSON body, headers, and timeout and returns decoded response data.

### OC-018 — Router compatibility
The engine MUST expose `name="openclaw"`, `capability_class="agent_runtime"`, configured locality, declared version, `supports()`, `health()`, `execute()`, and `normalize()`.

### OC-019 — Runtime attestation
If OpenClaw exposes `agentHarnessId`/runtime identity, it MUST be recorded. A requested runtime identity supplied by task metadata MAY be compared against observed identity, but the adapter MUST NOT claim enforcement when the Gateway omits attestation.

### OC-020 — Receipt layering
Existing `EngineExecutionReceipt` remains the provenance wrapper. This integration MUST NOT change `StationReceipt` schema or invalidate persisted verification/cache contracts.

## Request mapping

`TaskSpec.input` is converted into a labelled user input. `ContextAssembly.values` is serialized separately as context. The selected model is bound by immutable engine configuration. Optional task metadata may include:

- `allowed_tools`: iterable of Residual-authorized tool names.
- `worker_contract.allowed_tools`: alternate contract-projection location.
- `openclaw_runtime_id`: requested/expected runtime identity for provenance comparison only.
- `instructions`: additional non-authoritative task instructions.

OpenClaw runtime selection is expected to be configured in OpenClaw itself at model/provider scope. Residual records what it can observe; it does not rewrite OpenClaw configuration.

## Acceptance tests

1. Engine satisfies the protocol surface and router registration.
2. Deterministic request body includes separated task/context data.
3. Responses API `output_text` normalizes correctly.
4. Nested Responses API message text normalizes correctly.
5. Token usage normalizes from both supported shapes.
6. Allowed tool call succeeds.
7. Forbidden observed tool call raises `ContractError`.
8. Authentication token is absent from result metadata.
9. Runtime identity is recorded when present and marked unverified when absent.
10. Injected transport receives configured timeout and endpoint.
11. Health does not perform transport I/O.
12. Existing `EngineExecutionReceipt` and router behavior remain unchanged.

## Non-goals

- Replacing Residual's scheduler with OpenClaw sessions/subagents.
- Treating OpenClaw policy reports as Residual verification receipts.
- Remotely editing OpenClaw configuration.
- Claiming OS/filesystem isolation from an HTTP response.
- Persisting Gateway credentials in Residual evidence.

## Security posture

The Gateway is treated as an execution boundary, not a trusted evidence authority. Any security property required by Residual must either be enforced outside the Gateway by Residual's worker/runtime layer or be independently observable and checked. Unknown remains unknown.
